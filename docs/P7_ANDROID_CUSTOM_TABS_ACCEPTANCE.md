# Android Custom Tabs acceptance — P7 OPEN

This increment builds the normal React Native screen, not the native fixture
screen, and starts an owned API35 emulator with a fresh app installation.
Its new native journey is NOT EXECUTED until exact-head CI runs successfully.
The three selector unit controls are not native authentication evidence.

The driver uses actual UIAutomator accessibility nodes, taps, keyboard input
and Android Back. It requires the Chrome `CustomTabActivity`, correct app
package and original process on callback. Private authenticated communities,
one cookie-free native code exchange, PostgreSQL refresh-family rotation,
new-process Keystore restoration, cross-account isolation and revoked-token
rejection gate acceptance. Browser UI cannot satisfy native account checks.

Cases run once: actual CCT cancellation; A sign-in/consent/OS return and restart
rotation; B account switch, isolation, restart, sign-out/revocation and another
restart. Chrome cookies are not cleared between accounts to simulate isolation.
An unexpected retained browser account cannot count as successful switching.
No callback, password result, token, cookie or page JavaScript is injected.

## Test HTTPS trust

PostgreSQL16 and Redis7 are fresh service containers with no host volumes.
Only disposable test users and their refresh families are inspected. No
production data or existing database directory is accessed.

A one-run CA/127.0.0.1 server certificate is generated. The emulator's normal
Settings interface installs the CA after explicit confirmation and a generated
disposable device PIN. Android 11+ disallows CA installation through the app's
KeyChain install intent; see the official
[KeyChain API](https://developer.android.com/reference/android/security/KeyChain#createInstallIntent()).
No root writes, certificate-warning bypass or insecure browser flags are used.
The real login page must load in CCT before credentials are entered.

The generated DEBUG manifest alone trusts that public CA for loopback. The
scoped config preserves the debug Metro HTTP connection; Bridge auth/API origin
validation still requires HTTPS, with certificate/hostname validation enabled.
No CA private key is packaged, no production/release trust setting is changed,
and pinning is not disabled with debug-overrides. APK SHA256 and exact head are
retained. A first installation is required: the runner refuses to overwrite an
existing app or clear its data.

Raw accessibility XML/ADB command arguments and server logs stay outside
uploaded evidence. Closed phase/package/activity facts, build logs and
screenshots retain the first failure. Unstarted cases are NOT EXECUTED, zero
skipped acceptance cases, no journey retries.
